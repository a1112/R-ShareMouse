# RShare macOS Virtual Display Driver

This package is the macOS driver-side counterpart to `rshare_platform::virtual_display`.

The current implementation targets the public IOGraphics kernel API:

- `RShareMacVirtualDisplay` subclasses `IOFramebuffer` so the service can become part of the macOS display topology.
- `RShareMacVirtualDisplayUserClient` exposes the shared selector ABI through `IOUserClient::externalMethod` and accepts only a local logged-in user or an administrator.
- The R-Share control channel uses the dedicated `RSMV` (`0x52534D56`) connection type; standard framebuffer connection types are delegated to `IOFramebuffer` for WindowServer.
- `createOrUpdate` validates against the same supported mode table as Rust, allocates a shared 32-bit framebuffer backing store for the first requested mode, records `Pending`, and signals the connection-change interrupt path. An offline controller does not allocate VRAM, and the store only grows when a larger mode is selected, avoiding both an unnecessary startup allocation and a maximum-size contiguous allocation. Replaced prepared allocations are retained until `IOFramebuffer::stop()` returns; the remaining aperture map is then released before those physical pages are completed, so mode expansion and teardown cannot leave a mapping to recycled memory.
- The state moves to `Active` only after IOGraphics performs its connection check with the requested mode already selected, or after `setDisplayMode` commits that exact requested mode. A stale mode commit cannot overwrite a newer request. The superclass owns mode-change notification ordering after it remaps the framebuffer.
- `removeVirtualDisplay` marks the state `Removed` and sends the same connection-change path. IOGraphics publishes online/probed notifications only after it has processed that interrupt and reconciled the display topology.
- Connect interrupts are queued until IOGraphics registers its callback and serialized with unregister/stop, so an early create request is not lost and an in-flight callback cannot outlive the target it references.

`scripts/driver/build-macos-vdisplay.sh` builds the source into `target/macos-vdisplay/RShareMacVirtualDisplay.kext` using the local macOS SDK kernel headers. It defaults to a universal binary containing `x86_64` and `arm64e`, because Apple silicon kernels require the `arm64e` KEXT architecture. It compiles with conversion, sign-conversion, shadowing, and alignment warnings promoted to errors. It links each architecture as a Mach-O `KEXTBUNDLE`, verifies every requested slice, its `_kmod_info` module descriptor, and the metaclass constructor/destructor sections required by the IOKit C++ runtime, and rejects ordinary relocatable object output before packaging. Set `ARCHS` only for focused local diagnostics, and set `SIGN_IDENTITY` to codesign the bundle with a kernel-extension-capable certificate. The load and validation scripts require the universal architecture set unless `REQUIRED_ARCHS` is explicitly narrowed for diagnostics.

Run `scripts/driver/check-macos-vdisplay.sh` from the repository root for local SDK syntax and Clang Static Analyzer checks of the driver source.

For manual device validation after signing, use `scripts/driver/validate-macos-vdisplay.sh --load --verify-daemon-display-topology`. The validation script elevates only the KEXT installation step with `sudo`, leaving Cargo and daemon checks in the invoking user's environment. `sudo scripts/driver/load-macos-vdisplay.sh` first requires both `codesign --verify --strict` and `spctl -a -vv -t install` to accept the source bundle. It then installs the exact bundle at `/Library/Extensions/RShareMacVirtualDisplay.kext`, normalizes that installed copy to `root:wheel` with non-group-writable permissions, reruns signature and `kmutil print-diagnostics -z` checks, and submits it with `kmutil load`.

For an isolated development Mac that is already configured for Permissive Security with System Integrity Protection fully disabled, `ALLOW_UNSIGNED_KEXT=1 scripts/driver/validate-macos-vdisplay.sh --load` enables the unsigned development path. The scripts require both that explicit environment variable and the exact `csrutil status` disabled state before bypassing signing policy. They never change SIP, Startup Security, or KEXT consent settings. Do not use this path for distribution or on a normal workstation.

On macOS 11 and later, a newly installed third-party KEXT is incorporated into the Auxiliary Kernel Collection instead of being loaded into the running kernel on demand. The load script treats `kmutil` exit code 27 as `rshare_kext_state=approval_required` and exit code 28 as `rshare_kext_state=reboot_required`, rather than misreporting those expected transitions as hard failures. Approve the extension in System Settings if prompted and restart macOS. After restart, run `scripts/driver/validate-macos-vdisplay.sh --skip-build --verify-daemon-display-topology` to probe the user client with `cargo run -p rshare-cli -- display virtual driver-status --strict`, create the display, and verify it through the daemon. `sudo scripts/driver/unload-macos-vdisplay.sh` submits removal of `io.rshare.mouse.vdisplay`, removes the installed bundle, runs the required `kmutil rebuild`, and requires approval or a restart before the old Auxiliary Kernel Collection is replaced. Outside the explicit SIP-disabled development path, the load script refuses unsigned or install-policy-rejected bundles instead of relying on a later `kmutil` failure.

This is still not a validated shipping kext. Completing the feature requires Developer ID signing with the needed kernel-extension entitlement, loading on a test Mac with reduced security where required, and verifying that `rshare_platform::display::query_display_state()` reports the created `R-SHAREMOUSE` display after `cargo run -p rshare-cli -- display virtual create`.
